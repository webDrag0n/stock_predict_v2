A 股量化交易系统使用说明

从行情与因子到模型预测、样本外回测和次日订单。本说明面向日常使用者和研究人员，重点讲清“今天该点哪里、订单如何写回、结果如何判断”。

网页默认地址 127.0.0.1:8060CLI 可独立运行订单由人工在券商执行
交易边界

不是自动下单系统

系统只生成订单建议，不连接券商。实际委托、撤单和成交以券商终端为准。

每日必做

成交后维护现金与持仓

现金不会根据成交自动更新。现金过期会阻止夜间出单，持仓不实会使后续订单失真。

研究边界

样本外结果不等于未来收益

重点看跨窗口稳定性、成本后表现与留出段，不以单次 Sharpe 或历史排名作收益承诺。

没有匹配的章节。请尝试“订单”“模型”“回测”“日志”等关键词。
01

认识系统#

数据、模型、订单与文件状态组成一条可复现流水线。

STEP 1行情与外部数据
STEP 2因子与模型预测
STEP 3策略、风控与订单
STEP 4人工在券商执行
STEP 5成交、现金写回

系统能做什么

  • 从 Tushare 获取 A 股行情，并整合估值、北向持股等数据。
  • 计算技术与基本面因子，训练集成模型并预测未来收益排序。
  • 以每日重放、次日撮合进行 walk-forward 样本外回测。
  • 生成次日买卖订单，跟踪持仓、现金、风控和实盘偏差。
  • 提供公式因子编辑、模型门控、候选晋升与运行日志。

使用前要知道

  • 当前默认研究口径为全市场股票池、20 个交易日预测窗口。
  • 网页读取本地文件；终端任务不依赖网页也能完成并留下记录。
  • 网页中的长任务由同一批 CLI 在后台执行，关闭页面不会中断。
  • 行情页使用本地日线缓存，不是券商实时行情或交易接口。
  • 策略以仅做多 long_topk 为实际交易路径；做空类策略仅供研究。
三个核心目录：outputs/ 保存订单、账户、回测与运行记录；models/ 保存线上模型和候选；data_cache/ 保存行情与因子面板缓存。排错时先查这些文件，不必猜测页面内部状态。
02

安装与首次启动#

准备 Python、uv 和 Tushare Token，然后启动网页。

1. 准备环境

要求 Python 3.10 或更高版本，并使用 uv 管理依赖。以下命令均在项目根目录执行；把示例路径替换为本机实际目录。

cd /path/to/stock_predict_v2

# 如尚未安装 uv
curl -LsSf https://astral.sh/uv/install.sh | sh

# 网页 + 开发/测试依赖；自动创建 .venv
uv sync --extra ui --extra dev

# 如需 XGBoost / CatBoost 可选模型，再安装 full extra
uv sync --extra full --extra ui --extra dev

只做核心研究时可使用 uv sync --extra dev；要运行本说明中的网页，必须包含 ui 依赖。

2. 配置 Tushare Token

在项目根目录的 config_credentials.toml 中填写：

[tushare]
token = "你的 Tushare Pro Token"

也可使用环境变量 TUSHARE_TOKEN，其优先级更高。该凭据文件不应提交到版本库或发送给他人。

export TUSHARE_TOKEN="你的 Tushare Pro Token"
首次数据准备可能较久。首次下载全市场日线、估值和因子面板需要等待并受接口权限、限速和网络影响；后续通常使用本地缓存与增量更新。北向持股等接口还受 Token 权限与每日调用额度限制。

3. 启动网页

uv run python run_webapp2.py

终端显示 QuantLab v2 → http://127.0.0.1:8060 后，用浏览器打开该地址。停止服务可在启动终端按 Ctrl+C。

自定义端口或开发模式
# 修改监听地址与端口
HOST=0.0.0.0 PORT=8061 uv run python run_webapp2.py

# 开发热重载
DEBUG=1 uv run python run_webapp2.py

默认仅监听本机。改为 0.0.0.0 会允许其他机器访问；当前网页没有登录鉴权，不应直接暴露到公网。

4. 首次使用检查

已有持仓文件使用以下列名。股票代码保留交易所后缀；entry_date 为建仓日，ref_close 为持仓参考价。

symbol,shares,entry_date,ref_close
000001.SZ,1000,2026-01-05,10.80
600519.SH,100,2026-01-06,1450.00
现金不是总资产。“现金”填写实际可用资金，不是“现金 + 持仓市值”。首次没有 champion 时，可通过一次夜间任务自动 bootstrap，或先到“模型”页训练候选。
03

每日交易流程#

T 日收盘后出单，T+1 日人工执行，成交后写回并维护现金。

订单文件名日期是信号/行情日期。例如 orders_20261120.csv 通常表示用 11 月 20 日收盘数据生成、供下一交易日执行的订单，不是“11 月 20 日已经成交”的记录。

  1. T 日收盘后：生成次日订单

    在“交易”页点击 生成次日订单，或在终端运行：

    ./daily_run.sh

    网页按钮使用与脚本一致的 3 万本金预设；终端脚本还会先检查交易日，日历不可用或非交易日会安全跳过。任务进行中可点击“查看进度”，不必停留在原页面。

    小本金预设当前值含义
    --capital30000组合资金兜底；存在有效账户现金时以实际现金为准
    --max-positions6最大持仓只数
    --max-weight0.20单只目标权重上限 20%
    --min-notional2000忽略低于 2000 元的调仓差单
    --allowed-boardsmain新买单仅允许主板
    --skip-unaffordable开启跳过一手都买不起的候选并向后补位

    系统默认每 10 个交易日重新决策一次，非调仓日没有订单可能属于正常情况。不要为“补订单”反复强制执行旧订单。

  2. T+1 日开盘前后：核对并人工执行

    打开“交易”页的“订单执行单”，先做三项核对：

    • 订单未过期：出现“已过期，勿执行”时不要下单，应查明行情与订单日期后重新生成。
    • 拦截单不执行：标为“拦截 · 不执行”的订单由决策层排除。
    • 先卖后买：先处理卖单腾出资金，再按可用现金处理买单。限价、参考价和预计金额仅供委托参考。

    在券商终端完成委托后，回到网页逐笔点击 执行；决定不做某笔则点 拒绝。再次点击同一按钮可撤销该标记。“执行/拒绝”只是本地记录，不会向券商发送任何指令。

    每笔订单的“分析”可展开，查看选股、排名、风控与订单生成背景。

  3. 成交后：按实际情况写回持仓

    全部成交时

    使用网页确认

    当所有未拦截、未拒绝订单都已按订单数量成交时，点击 确认成交，写回持仓，在二次弹层中核对笔数，再点“确认写回”。

    网页会跳过拦截单和拒绝单，并假设其余订单全部成交。过期订单和疑似重复确认会被拦截。

    部分成交 / 价格不同

    使用实际成交单

    若有部分成交、未成交或实际数量不同，不要直接假设全部成交。准备 outputs/fills_YYYYMMDD.csv，再运行 ./daily_run.sh commit。

    脚本检测到当日 fills 文件后按实际成交写回；没有该文件时仍采用全部成交假设。

    实际成交单必须包含 symbol、side、shares、price 四列，方向只使用 buy 或 sell，股数与价格必须大于 0。

    symbol,side,shares,price
000001.SZ,sell,500,11.20
600519.SH,buy,100,1438.50
    # 推荐：成交确认入口；自动读取当天 outputs/fills_YYYYMMDD.csv（如存在）
./daily_run.sh commit

# 或显式指定实际成交单
uv run python predict_tomorrow.py --commit --fills outputs/fills_YYYYMMDD.csv

# 仅在确认所有有效订单均全部成交时使用全部成交假设
uv run python predict_tomorrow.py --commit

  4. 最后：维护现金并复核

    在“交易”页“现金”中填写券商成交、费用、分红和出入金之后的实际可用现金并保存。随后检查：

可选：定时执行夜间任务

可在工作日收盘并待日线数据就绪后运行。项目示例为 18:10；实际时间应根据数据源就绪情况调整。

# crontab 示例；替换为本机项目路径
10 18 * * 1-5  cd /path/to/stock_predict_v2 && ./daily_run.sh

定时出单不等于定时交易。次日仍需人工核对、执行、成交写回与现金维护。日志位于 outputs/job_logs/daily_YYYYMMDD.log。

04

七个页面怎么用#

顶部状态条显示运行、champion、现金与最新订单；侧栏切换页面。

总览 /

每天先看这里。除待办、champion、风控和运行状态外，还按最新订单落实状态展示当前持仓，支持再次编辑执行/拒绝、查看完整持仓历史、手动校正精确持仓，以及维护现金和交易费用设置。

  • 持仓状态：已执行、部分落实、待执行、已拒绝、无本批订单或已拦截。
  • 精确校正：按 CSV 编辑代码、股数、建仓日和参考价；保存后追加完整历史快照。
  • 个性化设置：佣金、印花税、最低佣金、冲击成本与参与率；新启动的出单和回测生效。

交易 /trade

完成生成订单、照单执行、成交确认、现金维护四步。还显示账户快照、目标仓位与当前仓位、持仓明细、实盘净值和五层风控。

“目标仓位”由订单推导，同样基于未拦截、未拒绝订单全部成交的假设。

模型 /models

管理 champion（线上）、staging（候选）与 archive（退役）。训练区用于生成候选并进入门控，评估区用于 rolling 或冻结工件的信号评估；两个区域分别显示启动反馈、当前步骤、任务步骤数、阶段进度/总步数、总耗时和阶段 ETA，只有对应任务全部结束才显示完成。

候选工件准备完成不等于整个训练任务完成，门控双回放仍可能在运行。no-new 表示没有新成熟标签并复用原参数，不显示为新增训练。晋升会替换 champion 并记录审计；删除 staging 是永久删除。

回测 /backtest

启动增量或滚动窗口 walk-forward，选择产物并查看净值、基准、窗口表、HOLDOUT、Deflated Sharpe、实验对比、冲击成本敏感性与试验记录。

长任务可能运行数小时。页面展示落盘产物，不会在浏览器里即时重算整套回测。

因子 /factors

按类别、准入、来源/状态和关键字筛选，查看 RankIC、ICIR、多空收益、换手、模型贡献、衰减与冗余簇。点击因子名进入六组详情图。

“新建公式因子”提供 DSL 校验、保存草稿和一键评估；草稿默认停用，不会自动进入线上模型。

行情 /market

搜索个股并查看 K 线、成交量、MA20/60、布林带、RSI 和 MACD，可切换近 1 年、近 2 年或全部缓存。下方展示全市场涨跌家数、涨跌停和平均/中位数涨跌幅。

遵循 A 股红涨绿跌。首次计算市场宽度约需数秒；数据截止日以页面显示为准。

运行 /runs

统一查看 CLI 与网页启动的后台任务，包括夜间出单、walk-forward、训练、信号/因子评估、偏差跟踪及终端成交确认。列表显示最近 60 条记录。

点击 run_id 查看步骤、实时进度、事件、产物、参数、失败堆栈和原始日志末尾；活任务可发送终止信号。

运行详情 /runs/<run_id>

排错的主要入口。先看失败步骤和错误摘要，再展开“堆栈”与“原始日志（末尾）”，最后核对“产物”是否真实存在。

运行中的详情页约每 2 秒刷新；终态后无需持续等待。关闭详情页不会停止后台任务。

因子研究页面的具体操作

操作步骤结果与注意事项
全库评估“因子”→“运行全库评估”更新因子评估表；公式库默认并不全部进入生产面板。
完整诊断“全库评估 + 诊断”额外生成 IC 衰减、相关矩阵和模型对比，耗时更长。
单因子评估进入因子详情→“评估该因子”原生因子使用面板；公式因子临时现算，不读写共享生产缓存。
新建公式因子“新建公式因子”→填写定义→“校验”→“保存草稿”→“立即评估”保存到 factor_library/custom.yaml，enabled=false；因子库变化会使下一次面板读取全量重建一次。
启用公式因子评估后按因子库规则编辑 YAML 与全局开关USE_FORMULA_FACTORS 默认关闭；启用不是网页保存草稿的自动后果。
公式因子 DSL 示例

例如创建一个 5 日动量因子：id 使用字母或下划线开头，只能包含字母、数字和下划线，最长 64 字符。

id: my_momentum_5
名称: 五日动量
类别: custom
预期方向: +1（越大越好）
公式: adj_close / ts_delay(adj_close, 5) - 1

常用函数包括 ts_delay、ts_mean、ts_std、ts_corr、ts_rank、cs_rank、safe_div、signed_power。编辑器会列出当前可用函数与依赖列；完整语法见 factor_library/README.md。

研究与模型晋升#

先验证信号，再做样本外回测，最后通过门控决定是否替换线上模型。

  1. 评估因子，而不是直接加进线上模型

    在“因子”页运行单因子或全库评估，结合 RankIC、ICIR、分层单调性、换手、近期衰减与相关性判断。通过准入代表有研究价值，不代表一定提升组合收益。

  2. 做信号评估，区分“排序力”和“可交易收益”

    在“模型”页选择 rolling（滚动重训）或 champion（冻结线上工件），点击“信号评估”。该任务只看 IC 与分位数收益，不经过实际撮合，不能替代 walk-forward。

  3. 用 walk-forward 检查跨时间表现

    在“回测”页选择引擎：

    引擎适用场景结果口径
    incremental评估与线上增量集成更接近的连续重放单一组合跨窗口连续，持仓和现金延续；窗口指标可从连续曲线切段复算
    windowed研究逐窗口训练与窗口内因子筛选每个窗口独立从空仓重放；窗口指标不与拼接曲线逐段相等

    比较实验时尽量固定数据快照、OOS 区间、本金、成本与交易约束。页面提示 OOS 区间不同，意味着差异不只是方法差异。

  4. 训练候选并查看门控

    在“模型”页点击“训练候选模型 → staging”。候选先进行门控评估，不会因训练完成自动替换 champion。重点查看 ΔSharpe、Δ回撤、评估天数、评估区间及警告。

    评估可疑时不要直接晋升。两侧指标逐项相同、champion 特征缺失、没有 evaluation.json 或门控未通过，都说明需要进一步核查。人工绕过这些警告时必须填写至少 6 个字符的理由，理由会进入审计。

  5. 对比后晋升

    在模型对比区设 A 为基准、B 为对照，页面显示 Δ = B − A。Sharpe、收益等通常越高越好；最大回撤为负数，越接近 0 越好，因此 Δ回撤为正通常表示改善。

    确认配方和特征差异后，在 staging 条目中点击“晋升”并二次确认。夜间任务运行时禁止晋升或删除候选，避免同一晚读取到不同模型。

研究纪律

只看样本外

训练段分数不能证明泛化能力。结论以拼接 OOS 曲线、正窗口占比和成本后结果为主。

留出段只做最终报告

HOLDOUT 之前的区间用于选型；不要为了改善结果反复查看并调整 HOLDOUT。

保留每次实验

最新 CLI 结果写入 outputs/walkforward/ 并可能覆盖前次。重要实验应复制到独立的 outputs/experiments/ 子目录。

当前推荐起点：保持全市场 UNIVERSE_MODE=all、20 日预测窗口和统一成本口径。旧的小股票池筛选方式已弃用；缩小股票池得到的结果不应直接与当前全市场结论混用。

指标怎么读#

不要只找“越高越好”的数字，要同时看收益、风险、稳定性与统计可信度。

指标含义阅读重点
OOSOut-of-Sample，样本外区间模型训练和选型未直接使用的数据；仍不能等同未来实盘。
Sharpe（净）单位波动对应的超额收益，页面使用成本后口径越高通常越好，但必须结合样本长度、正窗口占比和回撤。
Sortino只惩罚下行波动的风险调整收益适合与 Sharpe 对照，观察下行风险是否突出。
年化收益 / 总收益区间收益的年度化或累计表现核对 OOS 起止日、初始资金、成本和基准。
最大回撤净值从历史高点到随后低点的最大跌幅通常为负数，越接近 0 越好；评估自己能否承受。
Alpha / Beta相对基准的超额收益 / 市场敏感度Alpha 要结合 NW-t 和区间；Beta 不是越低或越高就绝对更好。
PredIC模型预测与未来实现收益的截面相关性衡量排序力；长期为正比单日极高更重要。
RankIC因子值排序与未来收益排序的相关性看方向、均值和跨窗口稳定性，不只看全区间平均值。
RankICIR / ICIRIC 均值相对其波动的稳定性绝对值较高通常表示信号更稳定，需与 IC 方向一起解读。
IC t 值IC 均值显著异于 0 的统计量绝对值约 2 常作为参考；仍需防止多重试验与数据窥探。
Newey–West t（NW-t）考虑时间序列自相关后的显著性统计量与 Alpha 方向一起读；页面以绝对值 2 作为徽章参考线。
正窗口占比Sharpe 或 PredIC 为正的 OOS 窗口比例衡量跨时间可复现性。增量引擎旧产物会以曲线复算值为准。
Deflated Sharpe考虑多次试验后的“真实 Sharpe > 0”概率越接近 1 越好；页面以 0.95 为参考线，试验越多折扣越重要。
换手率仓位变化与交易频率高换手会放大佣金、印花税与冲击成本，毛信号不一定能转化为净收益。
贡献分位 / 冗余簇因子在模型内的相对贡献 / 高相关因子分组独立 IC 高不等于边际贡献高；|corr|≥0.8 会在主表标注同簇。
页面可信度徽章：Sharpe>0 窗口占比达到 60%、PredIC>0 窗口占比达到 50%、|NW-t| 达到 2 时分别显示为通过色。这些是界面筛查线，不是收益保证或万能阈值。
实验噪声：项目页面提示，同一配置重跑的 Sharpe 随机波动约为 ±0.4。落在这个范围内的差异不应单独被当成改进证据。

五层风控乘数

“交易”页的总乘数由各层叠乘得到，只缩放目标仓位。显示“样本不足”或“已关闭”的层不参与有效降仓，不应把总乘数误解为收益率。

层当前默认行为主要输入
波动目标实现波动高于 15% 年化目标时降仓近 20 日已实现净值波动；历史不足时不触发
回撤刹车回撤超过 20% 时再乘 0.5已实现净值相对历史高点的回撤
IC 降仓近 20 日成熟 OOS IC 在 +0.02 与 −0.01 间映射仓位只有预测窗口已成熟的 IC；样本不足不降仓
择时 regime默认关闭大盘状态；启用后由决策端判定
IV 降仓隐波处于近 60 日高位区域时降仓opt_vix_like；数据不可得时显示未知

数据与状态文件#

页面是这些文件的视图；理解文件语义有助于避免重复成交和状态错乱。

文件 / 目录用途使用注意
outputs/orders_YYYYMMDD.csv次日买卖订单日期来自信号数据日；包含方向、股数、限价/参考价、原因和拦截状态。
outputs/holdings.csv系统认定的当前持仓由成交确认或总览“精确持仓校正”更新；与券商不一致时，下一批订单也会不一致。
outputs/holdings_history.csv每次持仓变更的完整历史快照订单确认、实际成交和手动校正都会追加；空仓也有记录，按 snapshot_id 分组。
outputs/trading_settings.json个性化费用与撮合设置总览页维护；新启动的出单和回测读取，环境变量优先，进行中的任务不改变。
outputs/account.csv每日实际可用现金网页保存会追加一行；最后一个有效 cash 用于估值，文件修改时间用于新鲜度检查。
outputs/fills_YYYYMMDD.csv券商实际成交记录四列必需；适合部分成交。daily_run.sh commit 只自动查找执行当天的文件。
outputs/execution_state_YYYYMMDD.json网页“执行/拒绝”标记按执行当天保存；只有“拒绝”会在成交确认时跳过，“执行”是进度记录。
outputs/live_risk_state.json净值与成熟 IC 等风控状态长期积累，不是普通临时缓存；不要随意删除。
outputs/live_risk_state_pred_hist.parquet历史预测分供未来标签成熟后计算真 OOS IC 与模型定权。
outputs/tracking/实盘偏差报告与每日快照网页“净值与偏差”和跟踪告警的数据来源。
outputs/runs/<run_id>/一次任务的完整记录run.json 为状态快照，events.jsonl 为事件流，run.log 为原始输出。
outputs/walkforward/最近一次 canonical 回测产物包含 meta.json、oos_curve.parquet、window_metrics.parquet、oos_bench.parquet；新运行可能覆盖。
outputs/experiments/独立实验与试验记录用于横向对比；trials.jsonl 的独立配置数进入多重检验修正。
models/champion/当前线上冻结工件包含 manifest 和模型文件；夜间未触发重训时直接使用。
models/staging/待评估或待决策候选训练完成不代表上线；已晋升候选可能保留同 id 副本。
models/archive/已退役 champion用于留档和模型对比。
models/promotions.log模型与网页写操作审计记录晋升、删除、现金、启动任务等操作。
factor_library/custom.yaml网页保存的公式因子草稿默认 enabled=false；修改因子库会改变缓存签名。
data_cache/行情、估值与因子面板缓存不是账户状态。排错时不要与 outputs 中的风控/持仓文件一起清空。

一次运行的目录结构

outputs/runs/<run_id>/
├── run.json        # 状态、步骤、进度、心跳、pid、产物与失败信息
├── events.jsonl    # run_start / step_start / artifact / error / run_end 等事件
├── run.log         # 原始标准输出与错误输出
└── reports/        # pipeline 步骤报告（适用时）

交易规则、成本与防泄露#

回测与次日订单共享决策及风控实现，但真实成交仍可能与模拟不同。

A 股撮合与成本口径

项目系统当前默认实际使用时的含义
决策与成交T 日收盘后决策，T+1 日行情撮合实盘订单也是供下一交易日人工执行，不能按 T 日收盘价假设成交。
T+1当日买入不可当日卖出由回测撮合层强制；实际券商同样需遵守。
交易单位1 手 = 100 股订单按整手生成；小账户可开启买不起即跳过。
涨跌停按次日价格与涨跌停条件判断可成交性被系统拦截的订单不执行；真实排队和流动性仍可能不同。
参与率单笔成交不超过次日成交额的 10%防止回测在大资金下假设无限流动性。
佣金买卖双边 0.02%，每笔最低 5 元小额订单尤其受最低佣金影响。
印花税卖出单边 0.1%属于系统回测配置，不保证等同当前券商或税费政策。
冲击成本默认开启，K = 0.1 的平方根模型订单相对成交额越大，估算冲击越高；可做敏感性分析。

以上费率是系统初始默认口径。可在总览“交易费用与撮合设置”中按实际券商修改并持久化；新启动的出单和回测会读取该设置，环境变量仍优先。回测产物的 meta.json 会保存当次费用快照。实际交易以券商费用和现行规则为准。

防泄露的关键约定

训练与测试之间有隔离带

EMBARGO_DAYS 默认等于 FORWARD_WINDOW，避免训练标签跨进 OOS 区间；配置要求隔离天数不得小于预测窗口。

只用成熟标签评分

20 日预测必须等对应未来收益已经实现后，才进入 IC 定权和 IC 风控，不能提前用未成熟结果。

因子选择只看训练段

启用窗口内因子筛选时，每个窗口仅用自身训练段选因子，不读取测试段表现。

决策与成交隔一天

因子与决策只使用决策日及以前数据，撮合使用下一交易日行情，避免把未来价格偷带进信号。

回测与实盘仍会有偏差。委托排队、部分成交、停牌、真实费用、现金维护延迟、数据修订和人工拒绝都可能造成偏差。应通过“偏差跟踪报告”和实际对账持续监控，而不是修改历史状态让曲线更好看。

状态与故障排查#

统一顺序：总览待办 → 运行详情 → 原始日志 → 对应状态文件。

运行状态含义

运行中
进程存在且心跳正常，可查看当前阶段、进度和预计剩余时间。
完成
任务正常写入终态；仍需检查产物和订单是否符合预期。
失败
展开失败卡片、堆栈和原始日志，定位具体步骤。
已终止
任务收到终止信号并写下终态；不要假设所有产物都已完整生成。
疑似卡住
pid 仍存在，但心跳超过 3 分钟未更新。先查日志与系统资源，再决定是否终止。
已中断
记录仍称 running，但 pid 已不存在，常见于强制结束或机器重启。该状态不能靠页面“终止”修复。

按现象排查

现象常见原因处理方法
夜间体检失败，退出码 3现金文件缺失、无有效 cash、现金超过默认 4 天未更新；或面板过旧、最新覆盖不足先维护真实可用现金，再查看失败条目。面板应更新到近期，最新股票数不得低于近 20 日中位数的 90%。不要常规使用 --skip-preflight 绕过。
订单显示“已过期”订单日期早于行情缓存最新日不要执行或确认。检查新行情为何已落盘，再用一致的持仓、现金和最新数据重新生成。
没有订单非调仓日、非交易日、前置体检失败、任务仍在运行或没有可执行候选先看“运行”页最后一步与日志。非调仓日无订单可以正常，不要盲目使用强制调仓。
提示已有重型任务夜间、回测、训练、模型/因子评估或冲击任务共用大内存面板等待现有任务结束，或进入其详情确认状态。网页对这些任务限制同时只跑一个，防止 OOM 和缓存冲突。
无法确认成交订单过期、疑似已确认、全部拦截/拒绝或没有订单按按钮旁原因处理。重复确认会重复加仓，不要强制绕过。
实际只成交一部分网页确认采用全部成交假设改用实际 fills CSV 的 CLI 流程，并按券商结果核对持仓与现金。
没有 champion首次使用或模型目录不完整运行夜间任务自动 bootstrap，或训练并晋升候选；确认 models/champion/manifest.json 存在。
champion 年龄告警超过 48 个交易日临近超龄，超过 60 个交易日超龄让夜间自适应重训与门控运行；必要时使用 --force-retrain，仍应检查结果而非直接替换。
候选不能晋升/删除夜间任务正在读取模型，或候选已不存在等夜间任务结束并刷新；未达门槛的晋升需填写理由。
回测没有 HOLDOUT / DSR读取的是功能加入前的旧产物用当前版本重跑；不要为获得更好看的结果反复移动 HOLDOUT 起点。
因子详情图缺失尚未评估、未通过准入，或未运行诊断先评估该因子；衰减/相关/模型对比需“全库评估 + 诊断”。分层与逐日 IC 通常只为准入通过因子落盘。
行情页为空没有 data_cache/tushare/daily_*.parquet先运行夜间任务准备行情缓存；同时检查 Token、权限、限速与网络。
修改代码后结果不变命中了因子或数据缓存先核对配置快照与缓存签名。仅在开发排错时有针对地清理相关数据缓存，避免误删账户和风控状态。

需要保留的排错信息

  • run_id、任务类型、开始时间和失败步骤。
  • 失败摘要、完整堆栈和 run.log 末尾。
  • 最新订单日、行情最新日、账户现金日期与 champion id。
  • 若涉及成交差异，保留原始 orders、实际 fills、执行标记及券商对账单。

常见问题#

日常操作中最容易混淆的行为。

关闭浏览器页面会中断任务吗？

不会。网页启动的任务由后台 CLI 子进程执行，状态持续写入 outputs/runs/。重新打开“运行”页即可继续查看。终端独立运行的 CLI 也不依赖网页服务。

点“执行”会真的向券商下单吗？

不会。它只在本地 execution_state_YYYYMMDD.json 记录执行进度。“拒绝”会让后续全部成交假设跳过该订单，但同样不会撤销券商委托。

为什么已经点了“执行”，现金还没有变化？

执行勾选不是成交入账。持仓需要成交确认或实际 fills 写回，现金必须按券商实际结果手动维护。

部分成交时，能否把未成交部分直接点“拒绝”再网页确认？

“拒绝”会跳过整笔订单，不能表达部分数量，因此不适合记录部分成交。应优先使用包含实际股数和成交价的 fills CSV；也可在总览“精确持仓校正”中按券商结果修正当前账本。两种方式都会保留完整历史，写回后仍需与券商对账。

训练完成后为什么订单仍使用旧模型？

训练产物进入 staging，不会自动晋升。只有门控通过并晋升，或首次 bootstrap 后，候选才成为 champion。模型页可查看当前线上 id 和晋升审计。

staging 中为什么出现与 champion 相同的 id？

晋升采用复制而非移动，已晋升候选可能留一份副本。这不是待决策的新候选，不需要再次晋升；确认无用后才考虑删除。

信号评估很好，为什么 walk-forward 收益仍可能差？

信号评估主要看预测排序，不完整反映仓位、换手、涨跌停、T+1、整手、成本和资金约束。可交易结论应以每日重放的成本后 OOS 结果为准。

可以直接在网页切换资金预设吗？

“生成次日订单”按钮固定使用当前 3 万本金预设。需要其他资金、持仓数、权重或最小订单金额时，使用带参数的 predict_tomorrow.py CLI，并确保参数与后续门控/回测口径一致。

为什么最新回测把之前的结果覆盖了？

outputs/walkforward/ 是最近一次结果的 canonical 目录，新运行会更新它；--compare 的两组运行也共用该目录，后一组覆盖前一组。重要结果应事先复制到独立实验目录，运行详情中的两组摘要仍会保留。

能否把网页部署到公网方便远程操作？

不建议直接暴露。页面包含现金维护、成交写回、模型删除/晋升和任务终止等写操作，且没有内置登录鉴权。默认只监听 127.0.0.1；远程访问应放在可信网络与额外认证层之后。

安全与风险边界#

把系统当作研究与订单辅助工具，而不是无人值守的交易代理。

账户与数据安全

  • 不要提交或传播 config_credentials.toml、Token、券商对账单和真实账户数据。
  • 定期备份 outputs/、models/ 与重要实验；尤其保留持仓、现金、风控状态和审计日志。
  • 不要把数据缓存与账户状态混为一谈。清理缓存前确认路径，不删除正在使用的工作目录。
  • 网页写操作应仅在可信环境使用；模型删除不可恢复，成交确认前应二次对账。

投资与研究风险

  • 历史回测、样本外指标和模型门控都不能保证未来收益。
  • 实际成交可能受涨跌停、停牌、流动性、排队和费用影响而偏离回测。
  • 不要仅凭单次 Sharpe、单窗口收益或单个因子 IC 做重仓决策。
  • 本系统仅供研究和回测辅助，不构成投资建议；使用者自行核对订单并承担交易决策责任。
每日最低安全动作：不执行过期订单；不重复确认成交；部分成交不套用全部成交假设；不让现金和持仓长期失真；不在夜间任务运行时切换 champion；不绕过体检与警告来掩盖问题。

设计哲学一句话
模型的已验证 edge 只有横截面排序（"哪只股票相对更强"），所以 ML 只负责选池； 何时买、买多少、能否成交，全部交给规则层与撮合层按 A 股真实规则处理。 每一层职责单一、可独立测试、可独立关闭。

01数据层：全市场、逐行无泄露、缓存可失效

模块：src/data/（tushare 连接器 + 因子工程 + 质量过滤）。入口：load_data() / load_factor_panel()

1.1 股票池构建：为什么是"全市场"而不是精选池

系统的研究结论（写入 config.py 注释）：横截面宽度是本系统最强的杠杆。49/300 只的精选池会破坏截面相关性结构、OOS alpha 不稳；只有全市场（~5300 只）产生了统计显著的真 alpha。因此默认 UNIVERSE_MODE=all，按交易日逐日拉取全市场行情（1 次 API 调用/天），中途被指数剔除或后来退市的股票仍在历史里——从数据源层面规避存活者偏差。

1.2 可交易性质量过滤（全部逐行、无未来信息）

1.3 Point-in-time 合并：外部数据永远不能"早知道"

三类外部数据按各自的可见时刻合并到日频面板，全部用 merge_asof(backward)：

数据可见性规则实现
估值快照（PE/PB/PS/市值）收盘后才发布 → 快照日期 +1 天才可见merge_fundamentals()
季度财务因子（ROE/毛利/增速）按公告日对齐，公告前用上一期merge_financial_factors() + 测试锁定滞后（年报+120天）
期权 IV / 全球宏观整体 lag 1 个交易日，缺失最多前向填充 3 天merge_option_iv_features() / merge_global_macro_features()

1.4 缓存签名：任何特征变更自动失效

防"陈旧缓存污染"机制
加工后数据集按签名缓存：md5(数据源 | 股票池 | 日期区间 | FORWARD_WINDOW | 各因子开关 | 因子源码内容哈希 | ...)。 因子代码（src/data/factors/*.py）改一行，签名就变，旧缓存自动作废。 同时落盘 *.features.json sidecar 记录"因子名 ↔ feature_NN 列号"映射，防止列含义静默错位。

02因子与标签：学什么、怎么定义对错

模块：src/data/factors/ + prepare_target_and_weight()

2.1 因子家族

技术因子（基础族）

动量/反转、波动率、布林带位置、RSI、量价相关等，永远开启。

正交异象因子

Amihud 非流动性、MAX 彩票效应、特质波动、残差动量、收益偏度、52 周高点距离——补上基础族缺失的 alpha 维度。

Alpha158 / GTJA191

Qlib 与国泰君安的公式化因子库精选子集（K线形状、趋势质量、分布位置、极值、量价持续性……）。

价值/财务因子

ep/bp/sp/dv_ttm 及截面排名、行业内排名；ROE/毛利/营收利润增速（point-in-time）。

行业特征

行业内相对估值排名（P0a 中和）、行业动量超额（P2 板块轮动）。

宏观/期权 IV

VIX、美债、美元、北向资金、ETF 期权 IV——日期级 regime 特征，经宏观×个股交互项获得截面方差。

2.2 标签 responder_6：模型到底在学什么

# 前瞻 N=20 日收益，用【复权价】计算（除权日不产生假收益）
fwd_ret = adj_close.shift(-20) / adj_close - 1        # clip 到 ±50%
responder_6 = fwd_ret - 当日同行业平均 fwd_ret         # 行业中性超额
  • 为什么用复权价：原始 close 在除权日跳变，会把"除权缺口"当成负收益注入标签（这是历史上把回测灌水的 bug）。
  • 为什么做截面超额：与 long_topk 的相对排名策略对齐——模型学的是"谁比谁强"，不是大盘涨跌（那是 beta，不是 alpha）。
  • 样本权重：逆波动 × 时间近因（0.5→1.0 线性加权，按日期全局百分位秩）。

2.3 防泄露的核心几何：前瞻窗 × Embargo

03模型层：增量集成 + 滚动 IC 定权

模块：src/ensemble.py · IncrementalEnsemble

全市场 ~5700 只 × ~600 个交易日的面板，每天全量重训要几个小时——不可行。解法是增量学习：

关键约束：定权 IC 也必须"成熟"
腿权重由"过去 N 个已成熟预测日的 rank-IC"决定。预测日 d 的 IC 要等 d+20 天（标签成熟）才能算。 模型层与风控层共用这条成熟性纪律——任何依赖 responder_6 的统计量，都要晚 20 天才能使用。
为什么默认腿是 gbm_l2 + ic_linear？（实验结论摘要）
  • ret_weighted 腿的独立 rank-IC 为负（-0.015，10 个 OOS 窗口只有 4 个为正），其高回测收益被归因为牛市 beta 而非选股能力——已从默认集成中移除。
  • ic_linear（+0.085，9/10 窗口为正）与 fusion（+0.100，10/10）承载了真实信号。
  • 3 个 seed 的内部 bagging 相关性 ~0.98，rank-combine 与 mean 统计无差异 → 默认 mean，保留价格空间诊断能力。

04决策层：从分数到精确订单

模块：src/trading.py · decide_orders() —— 回测与实盘共用同一个函数

仓位规模公式

每股目标金额 = min(
  总估值 × gross_leverage × risk_scale / 持仓数上限,
  总估值 × 单票上限 10%
)
股数 = floor(目标金额 / 价格 / 100) × 100

两种挂价模式

  • next_open（默认）：次日开盘市价成交
  • limit_bb：买挂布林下轨/卖挂上轨，次日价区触及才成交——换更低换手

06撮合引擎：用次日真实行情判定每一笔

模块：src/trading.py · simulate_fills() —— 决策在 t 收盘后，成交用 t+1 的 OHLC，天然滞后一日

6.1 A 股微观结构，逐项落地

涨跌停（按板块分档）

主板 10% / 创业板 30xxxx 20% / 科创板 68xxxx 20% / 北交所 30% / ST 5%。一字板用 high≈low（0.1% 容差）判定，反向单不可成交。

T+1（新增股数粒度）

t1_locked[代码] = (锁定日, 当日新买股数)。同日卖出单最多只能卖"老仓"部分——加仓不会把老仓锁死（修复前会）。

整手与现金约束

100 股一手；买入含成本循环缩手，绝不出现负现金；保守的每股成本估算先行过滤。

停牌与除权

停牌日持仓用 last_price 兜底估值（净值不假跌）；除权日用 pre_close 链条维护 val_factor，消除假性盈亏；单次调整幅度超 [1/3, 3] 判定脏数据跳过并计数。
每日双守恒断言（strict_check）
每个成交日校验：现金变动 == −买入额 + 卖出额 − 成本，以及 total_value == cash + 独立重算的持仓市值（含停牌兜底与除权因子口径）。 任何一处偏差 > max(1元, 1e-6 相对) 立即抛错——记账错误不可能静默累积。

07成本模型：三项成本，一个实现

trading.trade_costs() —— 每日重放引擎、周期调仓引擎、实盘事前估算三处共用（2026-09 重构前是两份平行实现，存在漂移风险）

# 佣金（双边，每笔最低 5 元）——A股券商普遍规则，纯比例会系统性低估小单成本
佣金 = max(成交额 × 0.0002, 5元)
# 印花税（仅卖出）
印花税 = 成交额 × 0.001
# 平方根市场冲击（小盘股的真实成本， flat 佣金掩盖不了它）
冲击 = 成交额 × 0.1 × √(成交额 / 次日成交额ADV)

每日重放引擎 run_daily_replay周期调仓引擎 run_backtest_periodic
抽象层级事件级逐笔（现金、股数、逐笔成交）权重级向量化（目标权重 + 真实日收益）
回答的问题"这套策略实盘跑会怎样？""这批预测分数的信号质量如何？"

成本trade_costs 逐笔trade_costs 向量化（同一代码）
用途pipeline 主回测、参数扫描（score_cache 复用）、webappwalkforward 滚动 OOS 指标、因子/目标评估
被删除的第三个引擎（教训）
旧 run_backtest（每日重叠调仓）已被删除且无回落开关：对 N 日前瞻目标，它每天在每条 entry 上重复计 N 日收益 （同一笔收益被 N 个重叠 entry 日计 N 次），且把 N 日步长当 1 日步按 252 年化——Sharpe/PnL 双重虚高。 项目规则：不要再引入"每天赚 pos×N日收益"的写法；没有逐日收益列时显式报错而非回落旧引擎。
score_cache：一次训练、多次重放
参数扫描时模型分数与"决策/撮合参数"解耦：先正常训练并收集 score_cache（{决策日 → {股票: 分数}}）， 后续每个参数组合只做决策+撮合重放，速度提升几个数量级。 缓存带指纹（特征列+ensemble 配置+前瞻窗的哈希）：指纹不匹配直接拒绝复用，防止陈旧分数静默污染实验。

10防泄露体系：四层纵深防御

第 1 层 · 数据可见性

估值快照 +1 天；财报按公告日（年报 +120 天滞后有测试锁定）；IV/宏观 lag 1；因子 IC 特征整体 shift(fw+1)。

第 2 层 · 标签成熟性

模型只见 d−(fw+embargo) 的成熟标签；IC 定权/IC 降仓只用已成熟预测日；import 期断言 EMBARGO ≥ FORWARD_WINDOW。

第 3 层 · 决策/执行时序

决策在 t 收盘后；成交在 t+1；估值用 t+1 收盘。决策→执行天然滞后一日，无未来信息。

第 4 层 · 对抗性测试

test_data_leakage.py：篡改未来标签，模型分数必须逐位不变；responder_fw_* 前缀永不进特征列；引擎层 embargo 断言。
最容易被忽视的两处泄露（本项目真实踩过）
  • 因子 IC 元特征：把"因子当日 IC"当特征时，IC 用了前瞻 20 日收益——rolling 之前必须整体 shift(fw+1)，否则测试窗内的特征含有尚未成熟的 IC（前视）。
  • 除权日标签：用原始价算前瞻收益，除权缺口会被当成暴跌标签。标签必须用复权价（adj_close），而成交价/估值用原始价 + val_factor——两个口径刻意分离。
